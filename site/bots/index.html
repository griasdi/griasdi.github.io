Bring a bot to the table.

spezl runs griasdi bots you write in Python or TypeScript. A bot is a member like anyone else: it has its own key, joins with an invite link and reads and writes the channels it can see. Slash commands, cards, polls, voice and video streams included.

spezl is coming soon. The Python and TypeScript SDKs come with its release.

What a bot is

  • A member with its own key. It joins a community through an ordinary invite link and has the same rights as anyone else. Nothing in griasdi changes for it, and no server has to allow it.
  • It reads what it can see. Like every member, a bot decrypts everything in every channel it can view. Channel audiences are the only boundary: keep a bot out of a channel to keep it from reading it.
  • It runs where you run it. On your computer or on a server of yours. spezl keeps its keys and state in one folder.
  • Its id starts with b07b. spezl searches a key until the user id begins with these two bytes, so apps can tell it is a bot. It is a convention of honest bot software, not a proof, and the app doesn’t show it yet.

What you need

  • spezl, a single program. It holds the griasdi client the SDKs talk to.
  • Python 3.10 or newer for the Python SDK, or Node 22.18 or newer (or Bun) for the TypeScript SDK. Neither SDK has dependencies.
  • For streaming video only: GStreamer with its base, good and bad plugins, and libav for H.264 and older formats.

Quick start

  1. Create the bot

    A fresh identity with a b07b… id. People mention it as @HelloBot.

    $ spezl new HelloBot

  2. Invite it

    Make an invite link as you would for a person, with Invite people › Create link in the community, and hand it to the bot. join tells you what the bot can read, for example HelloBot can read: #general.

    $ spezl join 'https://griasdi.github.io/join#invite:…'
$ spezl status

  3. Write it

    Pythonhello.py
    import spezl

bot = spezl.Bot()


@bot.on_ready
async def ready(server: str) -> None:
    print(f"{bot.name} ready on {server}", flush=True)


@bot.on_mention
async def greet(msg: spezl.Message) -> None:
    await msg.reply(f"hi, @{msg.sender.name}!")


bot.run()

  4. Run it

    $ spezl run hello.py

    Write @HelloBot hi in one of the bot’s channels. It answers hi, @<your name>!

The spezl command

  • new <NAME>

    Creates a bot identity. The first bot becomes the default.

  • join <LINK>

    Joins a community. Takes griasdi:invite:… or https://…/join#invite:… and returns once the bot is in every text channel it can view.

  • status

    Name, id, whether each server is online, and the communities with their text channels.

  • rename <NAME>

    Changes the display name and tells the members. Id, communities and folder stay. Stop spezl run for that bot first.

  • run <TARGET> [ARGS]…

    Runs a bot program with this bot’s home (below).

  • list

    The bots in the spezl directory; * marks the default.

  • default [BOT]

    Shows the default bot, or makes BOT the default.

  • serve

    The JSON-RPC sidecar the SDKs start themselves (protocol).

The bot’s home

Everything a bot owns is in one folder, its home. All homes live in the spezl directory: ~/.config/spezl on Linux, or another with --dir or SPEZL_DIR.

~/.config/spezl/
  config.toml        # default = "HelloBot"
  bots/
    HelloBot/
      identity/      # keys and certificates, unencrypted
      client/        # the griasdi client's database and MLS state
      members.toml   # members seen, so each join is reported once
      spezl.lock     # one process at a time
    PollBot/

The private keys are stored unencrypted. Treat a bot’s home like an SSH key. spezl new puts a .gitignore into every home, so git leaves it out.

  • A bot’s folder is its name without spaces and punctuation: Hello Bot becomes HelloBot.
  • Every command works on --bot <NAME> (or SPEZL_BOT), else on the default bot. Names match in any case, as display name or folder name.
  • --home <DIR> (or SPEZL_HOME) names one bot’s folder directly and wins over --dir and --bot.
  • Only one process may use a home: the second fails with another spezl process is using …. Stop spezl run before you call join or status for the same bot.

How spezl run starts a program

  • *.py

    uv run --project <dir> python <file> when uv is on PATH and the folder has a pyproject.toml, else python3 <file>.

  • *.ts *.mts *.js *.mjs

    node <file>, which runs TypeScript directly from Node 22.18; else bun <file>.

  • anything else

    The program itself.

The program gets SPEZL_HOME, the bot’s home, and SPEZL_BIN, the spezl it should start as sidecar. Ctrl-C and SIGTERM reach the program, and spezl run exits with its exit code (128+N for a program killed by signal N). You don’t need spezl run: set SPEZL_HOME yourself, or let the default bot be used, and put spezl on PATH.

Events and actions

Both SDKs give you the same events and actions.

Events

  • ready

    A server’s backlog has been processed.

  • message

    A text message by someone else in a community text channel: community, channel, seq, sender, text, reply_to and mentions_me.

  • invocation

    A member ran one of the bot’s slash commands.

  • press

    A member pressed a button on one of the bot’s cards.

  • submit

    A member filled in a form that a button on one of the bot’s cards opened.

  • member joined

    Someone joined one of the bot’s communities.

Actions

  • reply, send

    Answer a message, or write to a channel.

  • post card

    Post a card with buttons, lists, forms, columns, pictures, links or a poll.

  • edit card, replace card

    Replace the body of the bot’s own card (its buttons and poll stay), or its body and blocks in place.

  • delete message

    Delete the bot’s own message for everyone.

  • reveal

    Scroll the chat of the member who pressed a button or sent a form to one of the bot’s cards: the first reveal per press, within 10 seconds, on the device they pressed on.

  • upload image

    Store a picture for a card.

  • send DM

    Send a member a direct message.

  • communities

    List the communities and their channels.

What a message covers

  • Not the bot’s own messages, deleted messages, files or direct messages. A bot doesn’t read answers to its DMs.
  • Messages from while the bot was offline arrive like live ones when it reconnects, so it also answers mentions it missed. Invocations from that time arrive the same way.
  • mentions_me works the way the app highlights a mention: @<bot name>, in any case, as a whole word. A longer member name that also matches wins: @Anna Maria doesn’t mention Anna. @all, @here, @admins and @owner never count.
  • Sender names are the members’ display names. Right after join, a member’s app sends theirs to the bot within a few seconds.

What member joined covers

  • Once per join, also across restarts: the bot keeps the members it has seen in members.toml. A join while it was offline is reported when it starts again.
  • Not before the bot’s first start in a community: the members then are the baseline. Leaves aren’t reported; someone who leaves and comes back is reported again.
  • The event waits up to 30 seconds for the new member’s display name; without one, the name is the first 8 hex digits of their user id.

Python

Standard library only, Python 3.10 or newer. Handlers are async functions registered with decorators; an exception in a handler is printed and the bot keeps running. spezl.Bot(home=…, binary=…) overrides SPEZL_HOME and SPEZL_BIN.

  • @bot.on_ready@bot.on_mention@bot.on_message

    on_mention gets messages that mention the bot, on_message every message.

    msg.text, msg.sender.name, msg.sender.id, msg.sender.bot_id, msg.channel.name, msg.community.name, msg.seq, msg.reply_to, await msg.reply(text).

  • await bot.send(…)await bot.send_dm(…)

    send(channel, text, reply_to=None) writes to a spezl.Channel; send_dm(server, user, text) to a member by user id, opening the DM on the first one. await bot.communities() lists communities and channels.

  • @bot.command(…)

    command(name, description, fields=[…]) registers one slash command. inv.values maps field ids to values; await inv.respond(card, private=False) answers.

  • await bot.post_card(…)

    post_card(channel, card, to=None); to is the user id of the only member who sees it. Then edit_card(channel, seq, body), replace_card(channel, seq, card), delete_message(channel, seq), reveal(channel, action, target) and upload_image(channel, data).

  • @bot.on_press@bot.on_submit

    Presses and filled-in forms (submit.values, submit.card, submit.button). Both answer with await ….reply(text, private=False) and point the member at a card with await ….reveal(seq).

  • @bot.on_member_join

    Gets a spezl.MemberJoined: joined.community with its channels, and joined.member.

TypeScript

Only node: modules, no build step, on Node 22.18 or newer and on Bun. The same bot as above:

TypeScripthello.ts
import { Bot } from "@griasdi/spezl";

const bot = new Bot(); // new Bot({ home, binary }) overrides SPEZL_HOME / SPEZL_BIN
bot.onReady((server) => console.log(`${bot.name} ready on ${server}`));
bot.onMention(async (msg) => {
  await msg.reply(`hi, @${msg.sender.name}!`);
});
await bot.run(); // resolves when the bot stops (SIGINT/SIGTERM or bot.close())
  • Names

    camelCase throughout: msg.sender.botId, msg.replyTo, msg.mentionsMe, bot.sendDm, bot.postCard.

  • bot.send(…)bot.sendDm(…)

    send(channel, text, { replyTo }), sendDm(server, user, text) and communities().

  • bot.command(…)

    command({ name, description, fields }, handler) with fields such as { type: "textList", id, label, min, max, maxChars }; inv.respond(card, { private }) answers.

  • bot.postCard(…)

    postCard(channel, card, { to }), then editCard, replaceCard, deleteMessage, reveal and uploadImage.

  • bot.onPressbot.onSubmitbot.onMemberJoin

    Presses (press.reply(text, { private }), press.reveal(seq)), filled-in forms (submit.values, submit.reply) and new members (community, member).

Voice isn’t in the TypeScript SDK yet.

Commands and cards

A bot offers slash commands. In the app a member types / in a channel, picks one and fills in its form. The form is built on the member’s computer from the bot’s command list and stays there until they post it, so nobody else sees it. Posting sends the bot an invocation with the values, and the bot answers with a card.

Pythonpoll.py
import time

import spezl

bot = spezl.Bot()

ENDS = {"1h": 3_600_000, "1d": 86_400_000, "1w": 604_800_000}


@bot.command(
    "poll",
    "Start a poll",
    fields=[
        spezl.TextField("question", "Question", placeholder="What should we play tonight?"),
        spezl.TextListField("options", "Options", placeholder="Option", min=2, max=10),
        spezl.ToggleField("multiple", "Allow several answers"),
        spezl.ChoiceField(
            "ends",
            "Ends",
            [("never", "When I end it"), ("1h", "In 1 hour"), ("1d", "In 1 day"), ("1w", "In 1 week")],
            default="never",
        ),
    ],
)
async def poll(inv: spezl.Invocation) -> None:
    v = inv.values
    ends = ENDS.get(v["ends"])
    await inv.respond(
        spezl.Card(blocks=[
            spezl.Poll(
                v["question"],
                v["options"],
                multiple=v["multiple"],
                closes_ms=None if ends is None else int(time.time() * 1000) + ends,
                creator=inv.sender.id,
            )
        ])
    )


bot.run()

Form fields

  • text

    One line. spezl.TextField.

  • text list

    min to max lines. spezl.TextListField.

  • toggle

    Always arrives, a missing one at its default. spezl.ToggleField.

  • choice

    One of a few options. spezl.ChoiceField.

  • select

    A choice that can show its options as tiles (tiles) and depend on an earlier choice or select (on): an option with a non-empty when is offered only while that field holds one of its ids. A raid bot offers the specs of the chosen class this way. spezl.SelectField, spezl.SelectOption.

  • date and time

    Picked on the member’s own clock; the bot gets Unix milliseconds. spezl.DateTimeField.

All but toggles are required unless you say otherwise. Ids of commands, fields, options and buttons are 1 to 32 characters of a-z, 0-9, _ and -. An invocation of a command the bot doesn’t offer, or with values its form doesn’t accept, never reaches a handler. The SDK announces the commands in every text channel the bot is in, again on every connect and whenever a channel’s members change.

Card blocks

A card is a markdown body and blocks:

  • ButtonsHintedButtons

    Rows of buttons, optionally with hover hints. A press reaches the bot.

  • ItemList

    Rows of a bold title, a muted detail line and up to 3 buttons.

  • FormButton

    Opens a dialog with a form the bot defines: title, text, fields like a command’s and the label of its send button. What the member fills in arrives as a submit.

  • Columns

    2 or 3 markdown columns side by side, each up to 1000 characters.

  • Image

    At most two per card, from upload_image.

  • Links

    Up to 5 buttons that open an http(s) address in the browser. A press sends nothing.

  • Tally

    2 to 5 options of equal width, each listing the members who chose it. Everyone sees the counts and their own option marked; a press reaches the bot, which replaces the card.

  • Poll

    At most one per card. Votes don’t reach the bot: every member’s app counts them. Only a member’s newest vote counts, nothing after the poll ended or after closes_ms, and only the bot or the poll’s creator ends it.

Button styles are primary, secondary (default), danger, success, warning, disabled (shown, not pressable) and selected (the current choice, pressable).

Hidden is not secret

  • Votes are visible. Every member can read them; show_voters=False only hides the names in the app.
  • Private cards are hidden, not encrypted for one. A card posted with to shows only to that member, marked “Only you can see this”, and to the bot, and only their presses count. Every member’s app still receives and decrypts it. griasdi has no private text, so a private reply is a card.

Pictures

upload_image takes a PNG, JPEG, GIF or WebP, scales it to at most 1200 px per side (JPEG when opaque, else PNG), encrypts it and stores it on the channel’s server; the card carries its key. A picture belongs to one card: deleting the card, or replacing it with one that no longer shows the picture, deletes it on the server. Upload again for every card.

Voice

Python only for now. A bot made with spezl.Bot(voice=True) can be invited into a voice channel: a member in that channel right-clicks the bot in the member list and picks Invite to voice. Hovering the bot’s line under the voice channel offers Send home.

  • The bot decides itself, and takes an invite or a send-home only from a member who is in that channel.
  • It is in one voice channel at a time and leaves on its own once only bots are left.
  • It hears every other participant mixed, as 20 ms frames of 960 16-bit samples at 48 kHz mono, and plays the same format, at most 60 seconds per call. While 1 second of heard frames waits unread, newer frames are dropped.
  • The declaration goes into the community’s text channels, so a community without a text channel never offers the bot.
  • @bot.on_voice_join@bot.on_voice_leave

    Get a spezl.Voice: channel, community and by, who invited the bot or sent it home (None when it left on its own).

  • @bot.on_audio

    Every heard spezl.Audio frame in order: audio.samples is an array('h') of spezl.AUDIO_FRAME samples at spezl.SAMPLE_RATE.

  • await bot.play(samples)

    Plays an array('h') and returns once it is played. Raises SpezlError when the bot is in no voice channel or leaves before the end.

Streaming video

A bot streams a video file into a text channel as a screen share, without a voice call: bot.stream_file(channel, path, title=…, start_ms=…) in Python, bot.streamFile(channel, path, { title, startMs }) in TypeScript. The call returns once the share is live. The file waits at its first picture until the first member opens the stream, then plays in real time.

spezl decodes the file with GStreamer and encodes video with the first of these that loads:

  • AV1 on NVIDIA

    RTX 40 or newer (nvav1enc): up to 2560×1440, 30 fps, 10 Mbit/s.

  • H.264 on a GPU

    NVIDIA (nvh264enc) or VA-API, such as Intel or AMD (vah264enc): up to 2560×1440, 30 fps, 15 Mbit/s.

  • AV1 on the CPU

    svtav1enc: up to 1280×720, 30 fps, 2 Mbit/s.

An encoder that fails while the file loads falls back to the next. SPEZL_ENCODER=nvidia, nvidia-h264, va-h264 or software forces one, without fallback.

One file at a time: a new start, stop_stream or closing the bot ends the running one. Its end arrives as an event with the path, the reason (finished, stopped, failed with the error, or lost when the server ended the share) and the position reached, so the bot can resume there later.

To see what your system still lacks for streaming (it prints nothing when all is there; the three GPU encoders are optional):

for e in playbin svtav1enc av1parse avdec_h264 avdec_mpeg4 nvav1enc nvh264enc vah264enc; do
  gst-inspect-1.0 "$e" > /dev/null 2>&1 || echo "missing: $e"
done

The serve protocol

For an SDK in another language. spezl serve speaks JSON-RPC 2.0, one JSON object per line: requests in on stdin, responses and notifications out on stdout, logs on stderr (SPEZL_LOG sets the filter, default warn,spezl=info). Serve ends on EOF, SIGINT and SIGTERM.

  • Ids are lowercase hex. A server is its griasdi:server:… link.
  • info reports protocol: 2. An SDK should refuse any other.
  • A request without id is a notification: serve runs it and answers nothing.
  • Unknown keys are refused with -32602.

ts_ms is the sender’s own clock, unchecked. Never use it to decide what a member may do.

Values and data

  • values maps field ids to a string (text, choice, select), an array of strings (text list), a bool (toggle) or a number (date and time, Unix milliseconds).
  • samples are 16-bit little-endian samples at 48 kHz mono, standard base64 with padding: 960 per audio frame, at most 60 seconds for play_audio.
  • upload_image takes the file as standard base64. Its key and nonce come back base64; the key opens the picture, so keep it out of logs.
  • stream_file takes a path as serve sees it. A blank title is the file name without extension; start_ms defaults to 0. error in stream_ended is set only for failed.

Defaults: required is true for every field but a toggle, whose default is false; a select’s on is null, its tiles false and an option’s when empty; a form’s submit is “Submit”; a button’s style is secondary; a poll’s show_voters is true. Everything else is empty. A command set or card over griasdi’s limits (more than two pictures, a link that isn’t http(s), a member in two tally options and the like) is refused with -32602.

Errors

  • -32700

    Invalid JSON.

  • -32600

    Not a request.

  • -32601

    Unknown method.

  • -32602

    Invalid params, no such channel, data that isn’t base64, or JSON that isn’t valid Unicode.

  • -32000

    A griasdi or spezl error: no voice channel for play_audio, a picture griasdi can’t open, a file stream_file can’t play or a start offset past or too close to its end, a share griasdi refuses.
